## AI 协作的共用要求

T1 的三组内容分别使用：提示词模式帮助组织表达；协作工作流规定任务分解、上下文与边界、先写验收准则、人工审查与修订；输出核查分别检查引用、运行时事实、原理与实现、需求及规范依据。每个案例不必使用全部四种提示词模式，但不能省略适用的协作和核验步骤。

提示词可按本次任务填写：

> 基于【版本与代码范围】，先核实【现状】，再完成【本次子任务】。不得改动【接口、业务规则及范围】。验收按已确认的【输入、期望结果、失败与副作用约束】；尚未明确的条件先列问题，不替我决定。按“代码依据—方案与代价—修改建议—验证方法”输出，区分事实、推断与建议。保留原回答和差异，我将逐项核对后记录采纳、修改或驳回及依据。

人工核验记录并入已有一页说明及证据链接，不另加报告：引用项打开对应版本原文；运行项记录命令、输入、期望、实际输出与测试范围；原理项追踪实际实现和成立条件；依据项回到已确认需求及适用规范。本人注明实际完成的核验动作和修订，AI再次回答“正确”不能替代这些证据。

材料状态必须分开：**教学修订提示词**是本次可用模板，未执行就不写成真实交互；**历史记录**保留原日期、版本与结论；**AI辅助复核**表示由另一轮模型检查；**人工核验**必须有本人查看、运行或判断的记录。E5–E7旧核对文件的核对人是Claude，部分条目标明未运行，不能据此声称教师或学生已完成人工确认。旧E7记录曾建议降级，现版结论已撤回：替代路径未经验证时不放行，不能据旧记录直接降级。

### 教学重点与实施原则

E1–E7各新增两页主要步骤，供学生按“操作—检查—保留证据”随堂模仿，再迁移到个人选题。步骤导航不增加评分项或提交物，教师历史结果不能替代本人核验。核心概念、实验必需知识与考核方法均按必讲组织，选讲仅用于延伸。


以[教学设计总览](05-教学设计总览.md)的教学目标、必讲／选讲、实现手段和考核证据为依据。只标明必讲、选讲，不规定各环节时长；不为满足固定时间删页、压缩案例或降低概念解释的完整性。课件内容与案例保留，教师按学生理解和实践进度组织讲解、练习、讲评及延伸。

取消固定展示人数和个人展示时限，展示由教师按代表性问题和教学需要安排。课堂演示参与仍按答对演示小题计，仅投票不计参与；本次实验签到与作品展示参与分别记录。评分权重、讲清楚30／有依据30／验证过40及各子项、验收题集与判据保持不变。

课堂活动围绕目标形成可核查产物；未完成的实现、回归或在线验收如实标记并按既定提交期限补齐。部分产出不自动取得完整验证分，不用教师历史结果、AI复核、计划或离线替身代替本人实际证据。E2、E3、E4、E6通过可运行测试示例学习准备输入、调用公开入口、断言独立期望和读取结果，T7再系统解释测试理论。

### E1　开发环境与棕地仓库导读

**实验目标**：`mall-common`、`mall-mbg`、`mall-security`、`mall-admin`、`mall-portal`、`mall-search`、`mall-demo` 七个模块的结构与依赖；`mall-portal` 的"下单—支付—超时取消"调用链。

**理由**：这七个模块的依赖方向无环（`mall-admin`、`mall-portal` 依赖 `mall-mbg` 和 `mall-security`，`mall-security`、`mall-mbg` 依赖 `mall-common`；`mall-search`、`mall-demo` 依赖 `mall-mbg`），适合作为"开发视图"的第一个完整样本；`mall-mbg` 是生成代码模块，边界清楚，是讲"不得修改的部分"的天然入口。选"下单—支付—超时取消"而不是别的调用链，是因为它同时穿过控制器、服务、数据访问三层，并牵出消息中间件（延迟消息取消超时订单），一条链就能带出四张视图。

### E2　体系结构建模与方案评价

**实验目标**：运用 T2 的运行边界、信息隐藏和模块化，在调用链中识别具体问题或变化成本，不能只因类长、用了Mapper而判错。学生从[候选库](教学案例候选.md)选择非教师示例，给出文件:行号、调用者／数据流；比较两种最小改造方案，完成一处局部改动或可运行对照，用证据说明改善。教师演示 E2-00（取消订单 module：三个入口共用一个模块，补偿只写一份，行为保持）；扩展题 E2-01（订单状态流转 module，行为修正）。

**理由**：设计判断必须解释具体失败或变更成本，不能用方法长、依赖多、Service 调用 Mapper等表象机械判错。相关4+1视图作为模板，完整理论在后续 T3 学习；mall 与 mall-swarm 仅作背景比较，不强制部署两套。可测试性和改动成本比较保留；“两个方案写完”不等于“设计判断已验证”。

### E3　规格先行与 AI 结对编程

**实验目标**：教师演示 E3-00（Issue #47）以 `mall-admin` 的管理员登录为对象，围绕“用户名不存在与密码错误须返回同一响应码与同一文案”，完成“写规格 → 业务断言红灯 → 最小修复 → AI diff 审查 → 同断言绿灯及回归”。同分支的改密改造另作分层改进，不是消除登录红灯所必需的修改。

**理由**：T3 要求结合职责和变化分析契约耦合，不能把控制器转换失败码本身直接判为逻辑泄漏。本例的具体问题是登录失败响应不一致：登录链路中 null 与异常走向不同的响应处理，结果用户名不存在返回业务响应码 404（不是 HTTP 404），密码错误返回业务响应码 500 与"密码不正确"，调用方可据此判断账号是否存在。代码自己在 `UmsAdminServiceImpl` 第 272 行已写下统一文案"用户名或密码错误"，规格有据可查，现有测试又覆盖不到，因此天然要求"先写验收准则、再写失败测试"。该历史业务码不同于 T7 第8页教学示例的参数400／资源404方案。登录密码错误将 `Asserts.fail` 改为 `BadCredentialsException`，外层捕获 `AuthenticationException` 返回 null，控制器保留通用 `validateFailed`；改密服务把 -1／-2／-3 改为三条原文 `Asserts.fail`，控制器仅处理成功。历史同组测试为6项、1失败 → 6项、0失败，并非本轮复跑。P10–P11 是同一 `@Test` 的两段；改前在错误密码断言处失败，后续日志断言尚未执行。改密空参数的直接调用由返回 -1 改为抛异常，测试兼容两种协议；不能据此宣称所有行为保持或已验证 HTTP 校验路径。原积分示例（Issue #10）答案已公开，只作参考。

### E7　AI 功能接入与验收

**实验目标**：教师商品查询用于演示接入方式；学生从[候选库六项业务](教学案例候选.md#e7-business)选择订单问答、规格比较、退货材料整理、评论分类、属性提取或退货原因分析。提供普通业务实现和 LLM 业务实现（不是两种客户端传输），复用LlmClient，将模型理解与确定性业务处理分开；说明实际业务分工与取舍，以独立题集比较普通／LLM的结构化结果、耗时与局限，验证对抗、分布外及模型不可用处理，区分模型质量、接口单测和集成证据，给出放行／降级／驳回结论；关键证据不足时记为待验证、不放行。公开题集仅作课程回归，独立验收须记录来源与标注，开发不据验收题调参；正常通过率不等于覆盖率。

**理由**：六项都具有自然语言理解价值，并有字段、标签、集合或统计事实可核对。没有AI本身不是设计违规，不要求先制作不合格AI代码；新接入按其实际功能、职责及验收证据评价。模型不决定身份、权限、金额、数据库写入或统计求和；发生失败要明确返回，普通实现只有经过验证且能保持原任务含义时才可作为降级路径；普通路径不可靠时明确不放行。筛选及不选理由均在候选库 E7 节。

教师 `teacher-2026` 商品查询归档按状态与精确商品 ID 集合判分，不证明所有解析字段语义均正确。LLM 为19/20、7/8、4/4，普通实现为5/20、0/8、0/4；质量门槛未达标，两份报告的 `verdict=FAILED` 又采用全32题通过的判定，不能与 `qualityGate` 混为一谈。普通中位延迟5 ms、LLM约29.6 s；两题达约60 s客户端超时，不等于已经约定或满足业务时限。此例不放行，自动降级尚未验证。T7 的16项离线测试、8题待复核小样本、`java-holdout-1/2` 历史32题均为不同证据，不与本题集混用。 本轮未复跑。
